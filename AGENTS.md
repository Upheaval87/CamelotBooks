### Personal task list ("My Tasks", Aug 4, 2026)
- **`todo_tasks` table** — migration `2026_08_04_000001`. Personal + company-scoped: every query filters by **both** `company_id` AND `user_id` (`forCompany()`/`forUser()` scopes); `authorizeAccess()` in the controller 404s otherwise. No delegation/approval flow — a task is always owned by the creating user.
- **Deadlines**: store the end-of-period date (Sun 23:59:59 for week, last day for month, Dec 31 for year) + original `deadline_granularity` (`day|week|month|year`). `TodoTask::deadlineFor()` mirrors the JS chips in `resources/js/todo.js` (`todoDeadline` Alpine data, hidden inputs `<name>_granularity`/`<name>_date`).
- **Buckets** — `TodoTask::bucketKey()` shared by the controller's index grouping AND the dashboard counts so they always agree: `overdue`, `today`, `this_month`, `this_year`, `no_deadline`. View: `resources/views/todo/index.blade.php` (+ `_deadline-chips`, `_task-row`, `_task-row-completed`), CSS `.todo-*` in `app.css`, Alpine in `resources/js/todo.js` (registered in `app.js`).
- **Task detail modal** — a SINGLE shared `<x-modal name="task-detail">` rendered at page level in `index.blade.php`, OUTSIDE the `.todo-list` card. `.todo-list { overflow: hidden }` clips `fixed` descendants, so never nest modals inside it. Rows dispatch `open-task-detail` (window event with task data) → `todoDetailModal()` Alpine data (`todo.js`) populates state and opens the modal. Modal form posts via `:action="updateUrl"`, delete via `:action="deleteUrl"`. Deadline chips re-initialize per task via `:key="taskId"`. `@item-selected` on the modal body updates the link via `onLinkSelected`. **IMPORTANT — the containing-block bug**: `layouts/app.blade.php` wraps every page in `<div class="animate-fade-in-up">`. Its animation used `both` fill-mode and the `fadeInUp`/`scaleIn` keyframes end with `transform: translateY(0)`/`scale(1)` — even a "no-op" transform is a non-none `transform`, so the wrapper stays the containing block for ALL `fixed` descendants, breaking backdrop coverage (`fixed inset-0`) and centering (`fixed left-1/2 top-1/2`) of every modal app-wide. Fixed in `app.css`: `.animate-fade-in`/`.animate-fade-in-up`/`.animate-scale-in` fill mode changed `both` → `backwards` so no transform is retained after the animation ends. Do NOT re-add `both`/`forwards` to an animation whose 100% keyframe sets a transform, and NEVER rely on `x-teleport` to dodge this (teleported content with a nested `x-data`/component scope is fragile — `global-search-modal` uses it because its markup is self-contained, but a scoped component inside a teleport template breaks Alpine scope resolution). **No nested forms**: the delete `<form id="task-delete-form">` is a sibling AFTER the update form; the Delete button uses `type="submit" form="task-delete-form"` (a button outside a form can submit it by `id`). Browsers drop nested `<form>` tags, so a nested delete form's hidden `_method=DELETE` becomes part of the outer form and the submit deletes the task instead of updating it. **Link-resolution fix (Aug 4, 2026)**: `todoResolveLinkFromEvent()` reads the entity key as `item.groupKey || item.entity || item.type`. Global-search rows (selected via the magnifier) carry `type` (the catalog key) but NOT `entity`/`groupKey` — `selectResult(row)` passes the raw row from `group.results`, not the `flatRows` version. Before the fix, `entityKey` fell through to `''`, `linkableType` was empty, and `TodoTaskController::normalizeLink()` wiped the link on save (task kept its label visually until reload, then "No record linked"). Verified live in headless Chrome: inline dropdown + global-search magnifier both populate `linkable_type` and persist after save+reopen; modal Delete works.
