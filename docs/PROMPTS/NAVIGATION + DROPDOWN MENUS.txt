==================== 5 · OPEN / CLOSE BEHAVIOUR ====================
5.1 Desktop: panel opens on wrapper :hover AND :focus-within (CSS-driven; no click JS).
    Trigger open-state styling keys off the same selectors.
5.2 Bridge: wrapper ::after — invisible 14px-tall strip spanning the trigger width below
    it (top:100%), present only while open, so the cursor can cross the 12px gap without
    closing the panel.
5.3 Transition: opacity .18s ease + translateY(-6px)→0 + scale(.98)→1 (.18s
    cubic-bezier(.2,.8,.2,1)); visibility delayed .2s on close, 0s on open;
    pointer-events none→auto.
5.4 Touch / no-hover devices (@media (hover: none)): click on the trigger toggles an
    .open class on the wrapper (same visuals via .mi.open selectors); outside-tap and
    Esc close; only one panel open at a time. This is the ONLY sanctioned JS.
5.5 Keyboard: Esc closes any open panel and returns focus to its trigger; Tab into the
    panel keeps it open (focus-within); aria-haspopup="true" on triggers;
    aria-expanded synced (true while open by any mechanism); role="menu"/"menuitem"
    retained per APPENDIX A.
5.6 Remove ALL legacy dropdown open/close JS and old panel CSS once replaced; no dead
    handlers, no duplicate panels.
5.7 prefers-reduced-motion: disable entrance/stagger/transform transitions.
